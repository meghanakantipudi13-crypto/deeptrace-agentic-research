# Initial Risk Register

| Risk | Impact | Early mitigation | Evidence needed |
|---|---|---|---|
| Hermes plugin grading boundary | A technically supported plugin may still differ from the instructor's expected coupling | Use Hermes' official authenticated dashboard-extension path and ask the single Phase 8 confirmation question | Written confirmation plus deployed topology review |
| Cloud Run Instance beta availability/quota | Deployment could fail late | Run a Phase 0/1 account and region feasibility check as soon as tools/credentials are available | Successful minimal instance spike and cost estimate |
| Non-durable or corrupt state | Pending approvals or history disappear; malformed records crash history | Phase 5 separates official checkpoint savers from schema-v1 research memory; local SQLite/filesystem restart tests pass; GCS/PostgreSQL remain unverified | Live GCS and PostgreSQL restart tests before production claim |
| Decorative HITL | Retrieval proceeds without genuine approval | Implemented LangGraph interrupt plus code-enforced approval router | Scenario A checkpoint inspection and zero-search assertion; approve/modify/reject tests |
| Concurrent duplicate approval across workers | Research may execute twice after multi-worker deployment | Checkpoint state is authoritative and local lock remains a fast guard; official PostgreSQL saver is configured; GCS create-only writes reject overwrites | Multi-worker simultaneous-resume test against provisioned PostgreSQL |
| Live GCS behavior unverified | Mocked adapter may miss IAM, bucket policy, latency, retention, or quota failures | Use ADC, canonical UUID object names, create-only preconditions, bounded records, and explicit error logs | Credentialed save/load/list/restart test against the assigned bucket |
| Memory privacy or over-retention | Durable history could retain secrets or unnecessary external content | Persist typed terminal metadata only; omit prompts, headers, credentials, and retrieved bodies; cap records at 1 MB | Schema inspection, secret scan, retention-policy review, and live bucket IAM audit |
| Unauthenticated approval endpoint | Anyone who obtains a workflow URL could approve/cancel in a deployed build | Phase 4 is local-only; add authentication, authorization, CSRF protection, actor binding, and audit identity before deployment | Negative authorization/CSRF tests and approval actor trace |
| Self-correction only in prose | Advanced feature does not affect execution | Implemented typed critic and conditional router create changed queries and increment trusted iteration state | Scenario B trace/test showing a targeted second retrieval and reevaluation; repeat with live provider later |
| Poor or conflicting retrieval | Unsupported reports and weak metrics | Query decomposition, source quality rubric, diversity checks, conflict representation, safe uncertainty | Fixed-corpus and live-web evaluation cases |
| Direct or indirect prompt injection | User/retrieved text attempts disclosure, approval bypass, trust escalation, or graph manipulation | Phase 6 adds deterministic input blocking, retrieved-content quarantine, explicit trust envelopes, graph-enforced HITL/routes/counters, citation allowlisting, and structured redacted events; PI-001–003 pass locally | Repeat exact PI-001–003 against the authenticated deployed build; add broader variants and live-provider cases |
| Injection detector false positives/negatives | Blocks valid research or misses obfuscated or novel attacks | Detector is one layer alongside architectural controls; a quoted defensive-research control is accepted with annotation | Versioned benign/attack corpus, confusion matrix, encoding/obfuscation variants, and reviewed failures |
| Process-local rate limiting | A restart or second worker resets limits, allowing distributed abuse | Phase 6 bounds POST requests per client/route group in one process and returns a visible 429 | Authenticated identity-based shared limiter and multi-worker tests before deployment |
| Citation mismatch | Report appears sourced but claims are unsupported | Claim-evidence mapping, quote/span metadata where lawful, final validator | Citation correctness sample with human audit |
| Provider/API outage or drift | Demo failure and irreproducible evaluation | Adapters, timeouts/retries with caps, pinned versions where possible, cached licensed fixtures for tests | Failure-injection tests and provider metadata |
| Production silently uses fixtures | A demo could be mistaken for live research | Phase 8 fail-closed validation requires Vertex, Tavily, GCS, and PostgreSQL selectors and credentials/config | Production startup negative tests and visible LIVE provider banner |
| Cloud tooling/authentication absent | Live integration cannot begin or produce deployment evidence | Install Google Cloud CLI/container tooling, authenticate explicitly, select the actual project, and approve costs before provisioning | Tool versions, authenticated project output, and approved resource plan |
| Live Tavily behavior unverified | Mock contract may not expose account, relevance, quota, or latency problems | Run one bounded credentialed smoke test without recording the key before relying on live search | Dated request metadata, provider response, latency, and usage credits |
| Deterministic verifier is shallow | Lexical overlap may accept weak context or reject paraphrases | Treat scores as preliminary signals; later add calibrated model/human rubric and measure errors | Labeled relevance set and false-positive/negative analysis |
| Search snippets omit source context | Preliminary claims may lack full-document support | Label output preliminary; add restricted source fetching/extraction and span-level evidence later | Citation audit against fetched source text |
| Uncontrolled loops/cost | Budget exhaustion or runaway spend | Maximum two total retrieval passes; capped queries/results/sources; application-owned counters | Scenario C loop-exhaustion test plus future measured live cost records |
| Shallow sufficiency critic | Lexical coverage can misclassify strong paraphrases, weak mentions, or conflicts | Require explicit plan coverage, disclose heuristic status, terminate with uncertainty, later calibrate against labeled cases/model review | Scenario A/B/C state assertions now; future relevance/conflict benchmark and human audit |
| External web safety/SSRF | Future full-document fetching could access internal resources or oversized/malicious content | Current search adapter consumes provider-returned snippets only and has a bounded timeout; no general URL fetcher is present | Add URL/IP/redirect/MIME/size controls and isolated extraction before introducing document fetching |
| Sensitive data in traces/repository | Security incident and grading penalty | Redaction, `.gitignore`, secret scan before commits/pushes, minimal retention | Secret scan output and logging tests |
| Evaluation bias or synthetic sample | Deterministic scores may be mistaken for real research quality | Phase 7 freezes a 27-case, six-category v1 dataset, retains failures, reports designed gaps, and labels fixture latency/cost; live evaluation stays separate | Larger labeled live-provider set, human scorer calibration, deployed raw results, and sensitivity analysis |
| Demo complexity | Required behaviors are not visible in 5–10 minutes | UI event timeline, deterministic demo scenario, one visible guardrail | Rehearsed script and recorded dry run |
